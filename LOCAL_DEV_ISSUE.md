## What Turbopack Is Doing

Next.js 16 uses Turbopack as the default dev bundler. Turbopack has workspace root detection inherited from its Rust/Cargo toolchain that:

1. Walks the directory tree to infer where the "workspace root" is
2. Determines the "project directory" (the Next.js app within the workspace)
3. Restricts compilation to files within the project directory

Turbopack is incorrectly identifying the **project directory** as `next-platform-starter\app` (the Next.js App Router source folder) rather than `next-platform-starter` (the actual project root containing `package.json`, `node_modules`, `next.config.js`).

Consequences:
- `next/package.json` is not findable from `app/` — it lives at `next-platform-starter/node_modules/next/package.json`
- Files in `lib/lineup/` are outside the detected project boundary and cannot be compiled
- The dev server starts successfully but fails immediately on first compile

## What Has Been Tried (nothing changed the error)

### 1. `turbopack.root: process.cwd()`
```js
// next.config.js
const nextConfig = {
  reactCompiler: true,
  turbopack: { root: process.cwd() },
};
```
**Result:** Error identical. Project directory still reported as `next-platform-starter\app`.

### 2. `turbopack.root: __dirname` (via ESM imports)
```js
import { fileURLToPath } from 'url'
import path from 'path'
const __dirname = path.dirname(fileURLToPath(import.meta.url))
const nextConfig = {
  reactCompiler: true,
  turbopack: { root: __dirname },
};
```
**Result:** Error identical.

### 3. `turbopack.root: '../'` (parent directory)
```js
const nextConfig = {
  reactCompiler: true,
  turbopack: { root: '../' },
};
```
**Result:** Error identical.

### 4. `next dev --no-turbopack` flag
```
error: unknown option '--no-turbopack'
```
This flag does not exist in Next.js 16.2.6.

### 5. Deleting `.next` directory before running
Removes the `.next\dev\package.json` artifact. **Result:** Error identical.

## Key Diagnostic Observation

Despite three different `turbopack.root` values being set in `next.config.js`, the error message was **completely identical every time** — same detected project directory, same wording. This indicates either:

- `turbopack.root` is not being read in Next.js 16.2.6 on Windows, or
- It is read but does not affect the workspace/project directory detection

The production build (`npx next build`) works correctly on the Linux CI server. The problem is specific to **Turbopack dev mode on Windows**.
